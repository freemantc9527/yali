## 2. 范围

工作台覆盖添加、配置、批处理、结果与对比，预设和应用设置可独立管理。最小 640×420 窗口内能完成主流程；本批改参不改写 Finder 使用的预设。

保留 core / CLI 算法与 Profile / Settings Schema。持久化队列与统计归 T-018 / T-019，分类、抠图、OCR 和标定归 M3。不加暂停 / 取消、GUI 撤销、删除或覆盖原图、目录递归导入、托盘拖入、实时编码预测、浏览器编码、云或遥测。

## 3. 信息架构与主流程

主界面不设常驻左侧导航，只有工具栏、主工作区、参数 Inspector、底部操作栏。

```text
原生标题栏
┌──────────────────────────────────────────────────────────────┐
│ 添加图片   日常压缩 ▾                 预设管理  参数开关  设置 │
├──────────────────────────────────────┬───────────────────────┤
│ 图片数量 / 状态筛选 / 清空列表        │ 处理设置              │
│                                      │ 当前预设与用途摘要    │
│ 缩略图、文件名、体积、节省、状态      │ 格式 / 质量 / 尺寸    │
│                                      │ 保存位置 / 更多设置   │
│ 继续拖入图片                         │ 保存预设操作          │
├──────────────────────────────────────┴───────────────────────┤
│ 本批状态 / 节省汇总 / 输出说明         查看结果     压一下     │
└──────────────────────────────────────────────────────────────┘
```

手动主流程：添加/拖入 → 列表待处理 → 选择或调整方案 → 点击「开始处理」→ 逐张处理 → 汇总 → 对比或定位结果；完成后可换方案重新处理同一原图。

- 手动添加默认不自动压缩。开始前看到所用参数与输出位置。
- Finder「压一下」「转 JPG」保留现有静默行为，继续使用已保存预设。
- Dock/打开方式保留直接入队执行，使用 **default**；不得误用窗口里尚未保存的草稿或其他选中预设。
- 一次只运行一个 GUI batch；Rust 在该 batch 内沿用 `min(cores-1,4)` 并发。系统新批次排队，手动新文件暂存。
- 当前卡的运行中任务只覆盖 GUI command；不声称自动收集 CLI、watch、剪贴板的全部任务历史。

### 主按钮与清空语义

| 状态 | 主按钮 | 其他行为 |
|---|---|---|
| 没有文件 | 开始处理，禁用 | 拖入区显示添加入口与正式吉祥物 |
| 有待处理文件、草稿有效 | 开始处理 N 张 | 点击后冻结本批参数快照 |
| 处理中 | 处理中 · 已完成/总数，禁用 | 仍可添加新文件，明确显示“等待下一批” |
| 全部终态，无新文件 | 重新处理 N 张 | 确认后按当前方案处理原图，新建 attempt / batch；同名结果可能替换，其他名称的旧结果保留 |
| 终态且有待处理文件 | 开始处理 N 张 | 仅处理 pending 项，已有成功项不再次提交 |
| 存在失败项 | 行内重试；批量操作“重试失败项” | 新 attempt 使用当前草稿，并明确操作对象数量 |

“清空列表”只移除内存展示，不删除任何磁盘文件；有 batch 运行时禁用。完成后更改参数不会自动执行，重新处理需明确确认。默认“当前图片”只展示每张原图的最新任务；可用会话批次选择器查看先前处理，默认列表移除一张图时同时移除其旧 attempt，避免旧行再次出现。

## 4. 任务列表与结果

### 列表内容

- 行结构：缩略图；文件组（文件名、尺寸 / 格式 / 处理次数）；结果组（原始→结果体积、节省与状态）；操作组（对比与更多菜单）。再次处理、从列表移除归入更多菜单，避免并列碎列。
- 默认显示全部；筛选项为全部、待处理、处理中、已完成、未减小、失败，只呈现有意义的数量。
- 文件名可中间截断但保留扩展名；hover/focus 可获得完整名称与路径。按钮、数值与状态标签不截断。
- 同一待处理集合按规范化绝对路径去重；不同目录同名文件保留，显示父目录区分。相对路径不参与真机执行。
- 逐行移除仅适用于未运行项；移除不操作磁盘。当前 batch 已运行的项不可移除。
- 列表和 Inspector 独立滚动，底部动作始终可达。100 项不同时解码 100 张原图。

### 终态文案

| 内部结果 | 用户可见状态 | 处理 |
|---|---|---|
| pending | 待处理 | 等待手动开始 |
| queued | 排队中 | 已提交到 batch，等待执行 |
| processing | 处理中 | 不显示没有来源的单图百分比 |
| done 且变小 | 已完成 | 显示体积与正向节省百分比 |
| done 且转格式后变大 | 已转换，体积增加 | 用中性色/提示色说明，不伪装成节省 |
| larger_output | 未减小，已保留原图 | 没有产物，不提供虚假的“打开结果” |
| failed | 处理失败 | 行内可读摘要、展开原始错误、重试入口 |

进度按终态张数 / batch 总张数计算，失败和未减小都计入已处理；“成功 N 张”与“已处理 N 张”区分。SSIM 仅在对比时按需计算，不为每个任务后台批量跑。

### 汇总计算

按当前图片集合或选中会话批次的完整结果汇总，不随状态筛选改变。底栏第一行集中显示完成数、失败 / 未减小和节省量，第二行说明保存位置与原图保留；右侧为查看结果、开始 / 重新处理。`done` 用真实输入 / 输出字节；`larger_output` 用原始字节作为有效输出，节省为 0；失败独立计数，不计入字节。

总节省为总有效输入减总有效输出，百分比用汇总字节加权；不直接读 `savedPct` 或平均行百分比。净增加写「增加 X%」，分母为 0 显示不可计算。`formatBytes` 统一按 1024 换算。

「查看结果」单目录直接定位首个有效产物，多目录列出目录与产物数供选择。

## 5. 参数与预设

### 状态语义

`savedProfile` 是最近从磁盘读取或成功保存的完整预设。`draftProfile` 是本批草稿，保留未展示字段；dirty 比较内容，切换有改动的草稿前确认放弃。提交时深拷贝受控草稿为 `submittedProfile`，本批全程固定，运行期间参数只读。

内置预设仅四档，显示顺序为 default（日常压缩）、jpg（转 JPG）、thumbnail（缩小尺寸）、archive（无损归档）。缩小尺寸最长边默认 1024px，锁定宽高比、不放大小图；再按名称排序自定义档，只显示实际存在的预设。

### 参数分组

| 层级 | 字段与控件 | 规则 |
|---|---|---|
| 常用 | 输出格式，Select | 自动/JPEG/PNG/WebP/AVIF/HEIC/JXL，与现有输出枚举一致 |
| 常用 | 质量模式，Select | 压缩强度/目标大小/无损；不能用一个滑杆含糊表达全部模式 |
| 常用 | level，Slider + 数值 | 1 至 10；左“更清晰”、右“更小体积”；按格式说明，不许写预测体积或保证画质百分比 |
| 常用 | targetBytes，Input + 单位 | KB/MB 按 1000/1000000 写回整数 bytes；标明“目标为参考，受画质下限影响”，保留既有 floor 值，不新增保证 |
| 常用 | 无损 | 隐藏强度滑杆，呈现所选方案摘要；不把所有格式组合宣称为可逆归档 |
| 常用 | 图片尺寸，Select + Input | 保持原尺寸，或限制最大宽高；使用已有 resize.mode，常用限制走 shrinkOnly |
| 常用 | 保存位置，Select + 原生目录选择 | 原图文件夹、下载、自定义；已有 override 档显示“跟随调用环境”，不丢弃其值 |
| 更多 | 动图策略 | 保持 GIF / 转 WebP，明确用途 |
| 更多 | 后缀模板 | 展示实例说明，保留 `{profile}`/`{date}`/`{size}`，非空校验；修改不改原图文件名 |
| 更多 | 撤销记录开关 | 对应 undoManifest；文案“保留撤销记录”，不同时提供尚未实现的 GUI 撤销按钮 |
| 更多 | 元数据与颜色策略 | 保留现值但本卡只读，不新增“已移除 GPS”等保证；验证生效应另立核心任务卡 |

保持原图比例为默认，不新增自由拉伸/智能裁剪。导入的特殊 resize 模式保留并显示其现值，用户选择常用尺寸方案时才明确替换。pipeline 专家、分类、AVIF 速度、并发和 dither 不做无后端支持的旋钮。

尺寸、数字与路径错误贴近字段显示；本地预检只是提前提示，Rust `Profile::validate()` 是执行/保存权威。空白输入可以保留为编辑中字符串，提交时禁止 NaN、负数、小数尺寸与超范围 level，不以 `Number(x) || 默认值` 吞掉非法输入。

### 持久化操作

- Inspector 显示“仅调整本批，不改变已保存预设”。
- “另存为预设”使用 Dialog；名称沿用 Store 的规则，重名必须明确确认替换，成功后选中新档并同步 saved/draft。
- “更新当前预设”位于菜单；更新 default/jpg 前显示会影响 Finder 快速操作与后续后台入口，确认后才写盘。
- “管理预设”使用独立内容视图，带返回工作台入口；列出现有档与用途，保留另存、复制 JSON、粘贴导入，不常驻 JSON 文本框。
- 导出剪贴板失败就在界面提供只读 JSON 文本与复制重试，不要求用户打开控制台。
- 导入先 parse，再内核 validate，再确认重名；失败保留粘贴内容与当前工作草稿。
- 不增加删除预设、重命名磁盘档或修改右键绑定功能。

## 6. 对比与设置辅助视图

### 对比查看器

- 行内“对比”或选中行按 Space 进入独立大画布视图，顶部明确“返回工作台”；Esc 返回并恢复列表焦点/滚动位置。
- 仅有有效产物的任务可做前后对比；未减小可查看原图，但不显示不存在的结果。
- 同尺寸默认叠加，前后叠图使用同一画布与可见区域。标签固定为原图/处理后，并标明各自像素尺寸，不随分割线位置造成含义反转。
- 拖动分割线、键盘方向键调整、适应窗口/原始尺寸；原始尺寸按实际像素显示，超出窗口可滚动查看。使用固定尺寸方框图标，不暗示任意放大；上一张/下一张在当前有结果的任务中切换。
- 分割操作只保留画布上的分割线，移除底部滑杆与说明区域，释放高度给图片。
- 若处理后尺寸不同，默认并排，各自在可用宽高内完整显示并标明尺寸；可主动切换叠加并拖动分割线。适应窗口下按画面对齐、保持各自比例，明确提示对齐显示；原始尺寸下以各自实际像素居中显示，不拉伸图片。并排/叠加与显示尺寸可独立切换；尺寸变化时说明 SSIM 不适用。
- SSIM 异步显示 4 位小数；失败只影响指标，不阻止看图。切换任务后忽略旧请求结果。
- HEIC/JXL 等 WebView 无法直接显示时，使用 §9 的本地预览副本；保持结果路径指向真实原产物。
- 输入框、Select 或 Slider 获得焦点时，Space/方向键执行控件自身行为，不劫持为全局快捷键。

### 应用设置

- 工具栏齿轮或 ⌘, 进入独立设置视图，保持返回入口；不挤入工作台 Inspector。
- 分“通用”“自动化”两个 Tabs。通用：字体大小（滑杆六档 80 / 100 / 120 / 150 / 180 / 200%，默认 100%）、菜单栏常驻、通知、关于与真实内核版本；自动化：剪贴板监听、监视文件夹。滑杆按档位索引逐步切换，下方刻度逐项显示 80% / 100% / 120% / 150% / 180% / 200%，上方不重复显示当前数值；辅助技术仍可读取当前百分比，键盘方向键每次切一档。
- 字号保存到 `~/.yali/settings.json`，保存成功后全局生效，启动时恢复；界面文本使用 rem，弹层与公共控件同步放大。
- 从 settings_show 读取完整对象；明确点击“保存设置”才 settings_save；保存失败保留草稿，离开有修改时确认放弃。
- 通用页显示图片缓存占用 / 256 MiB、使用中占用与“清理缓存”；清理经确认立即执行，保护使用中的副本，保留原图、产物、配置及撤销记录。
- 剪贴板/watch 默认值从当前后端读取，不重置已有配置；首次默认 clipboard.enabled=false、watch.enabled=false、tray.enabled=true、notify.enabled=true。
- 自动化说明当前使用 default 预设；剪贴板输出到下载目录。监视目录用原生选择器，去重、显示完整路径；移除只移出监视清单，不删除目录。
- minBytes/settleMs 默认分别为 **65536 bytes / 800ms**，实际以当前 Settings 为准；高级折叠区可调整，保留 Rust 范围校验，不另存 localStorage。
- 关闭菜单栏常驻后，说明关窗会退出；保留后端现有行为，不在本卡重写托盘。
- 本卡不添加设置重置、开机启动或未实现的通知行为。

## 7. 响应式和窗口高度

断点以 **WebView 内容区 CSS px** 为准，不按图片像素或屏幕分辨率判断。

| 宽度 | 布局与密度 |
|---|---|
| ≥1100 | 主区 `minmax(0,1fr)` + 320px Inspector；文件 / 结果 / 操作分组；缩略图 64×48 |
| 960 至 1099 | 双栏，Inspector 280px；缩略图 64×48，格式/尺寸转次行，体积紧凑对齐 |
| 800 至 959 | 单栏；工具栏“处理设置”控制任务主面板下方内联 Collapsible，默认收起；缩略图 64×48 |
| 640 至 799 | 单栏紧凑任务行，体积与节省移到次行；参数表单两列可换行，工具栏次要操作进 DropdownMenu |
| <640 | 浏览器窄屏演示；参数单列，缩略图 48×48，底部汇总与操作分两行；触控目标至少 44px |

- Inspector 开/关状态由 App 统一持有，不由每个宽度分支各自初始化；跨断点只改变容器布局，草稿/选中项/任务不丢失。
- 参数表单复用同一个组件与受控数据，不同时渲染两套可交互表单制造重复 ID/Tab 顺序。
- 不用模态抽屉解决普通窄屏溢出；960px 以下参数在任务主面板下方内联展开，与任务区共同滚动，底部操作栏固定可达。
- 桌面普通控件高 36px；窄屏触控放大；可见文字字号不为塞布局而整体缩小。
- 原生窗口保留默认 980×640、最小 640×420。默认尺寸必须展示可用双栏，不能依赖 1536px 才像效果图。
- 内容区采用工具栏/主体/底栏三行 Grid，主体 `min-height:0`，列表与 Inspector `overflow:auto`。
- 高度 ≤520 时收紧分组间距，次要说明折叠；不隐藏关键按钮，不让底栏覆盖最后一行，不靠滚动整个窗口找主操作。
- 390px 仅验收浏览器布局，不声称此卡发布手机应用或浏览器压缩产品。

## 8. 视觉系统与 shadcn 组件

### 技术方案

保留 React 19 / TypeScript / Vite 版本范围与 Tauri 2 / Rust。按需引入 shadcn/ui 的 Radix 控件源码，样式用 Tailwind CSS 4 + `@tailwindcss/vite` 与 CSS 语义变量，图标用 Lucide。以主题变量和 variant 调整控件，保留底层焦点管理；不混用 Base UI、第二套 CSS 框架或全局状态服务。

### 主题初始值

以下为基于认可效果图的实施基线，可为对比度和真机渲染做小幅调整，不另开一轮风格设计。

| Token | 初始值 / 规则 |
|---|---|
| background | `#FAFAF7`，工作区 |
| inspector | `#F1F2EC`，相邻区域用 1px divider 明确分隔 |
| control/popover | `#FFFFFF` |
| foreground | `#242B24` |
| muted-foreground | `#626A5D`，必要时加深至满足小字对比度 |
| primary | `#557449`，白色文字 |
| selection/accent | `#EAF0E3`，深色文字 |
| border | `#DDE2D6`，交互边界与 focus ring 另满足可辨识性 |
| warning | `#91621D`，同时给文字/图标，不只靠颜色 |
| destructive | `#B43C36` |
| radius | 控件 6px，区域/选中行 8px，外层内容 12px；chip 可 pill |
| spacing | 4/8/12/16/24/32px；主区内边距宽窗 24px、普通 16px、窄屏 12px |
| font | `-apple-system, "SF Pro Text", "PingFang SC", system-ui, sans-serif` |
| type | 页面标题 18/600，区域标题 14/600，正文与控件 13 至 14，辅助文字 12；数值 tabular-nums |

主题写到 shadcn 的 background/foreground/primary/secondary/muted/accent/border/input/ring 等语义变量，增加 inspector/success/warning 等少量项目角色；可转换为 OKLCH。正文对比度 ≥4.5:1，控件边界与焦点状态满足可访问性要求。

保留系统深色支持：用同一语义变量提供深色映射，优先保证功能、对比度和图片背景中性；浅色稿是本轮视觉对照基准。跟随 `prefers-color-scheme`，不新增持久化主题设置。深色不使用亮绿色大面积铺底。

| 场景 | shadcn 基础 |

| 工具栏/菜单/图标按钮 | Button、DropdownMenu、Tooltip、Separator |

## 9. 接口与数据流实施约束

### 9.1 bridge 与原生能力

Tauri 调用集中在 `ui/src/lib/bridge.ts`，业务组件不直接 invoke。官方 dialog 提供图片多选（取消返回空集合）和单目录选择，opener 的 `revealItemInDir` 定位真实产物，`convertFileSrc` 生成本地图片 URL。图片扩展名对齐 `supported.rs`，实际格式由 Rust 魔数判断。

`capabilities/default.json` 保留 `core:default`，只增 dialog open 与 opener reveal 权限；不授予任意 shell 命令或网络打开能力，也不扩大已有本地 asset scope。

### 9.2 批次 command

`invoke("compress_batch", { request: { batchId, items, profile } })`，字段 camelCase。`batchId` 非空，`items` 为 `{ jobId, path }[]` 且 jobId 批内唯一；`profile` 是完整草稿快照。ID / 结构 / Profile 非法时在 warmup 和编码前拒绝，不产生文件。有效请求中的编码或 join 失败独立返回，不覆盖同批成功项。

返回 `{ batchId, outcomes }`。每项含 `jobId`、`path` 与终态：`done` / `larger_output` 有 `report: CompressReport`，`failed` 有 `error`。`yali://batch-progress` 额外携带 `batchId`，状态还包括 `started`；`report` / `error` 按状态可选。

command 的终态权威，事件用于即时反馈；按 batchId / jobId 更新，重复事件幂等，迟到 started 不覆盖终态。旧 `compress(paths, profile)` 与新接口共用执行器并保留兼容行为。开始压缩不写预设，取消和跨重启恢复未实现。

### 9.3 前端调度

App reducer 持有队列与选择，业务组件用 props。每项含 jobId、batchId、canonical path、source、attempt、status、report / error；图片信息与预览单独缓存。以 ID 对账，不按文件名或路径后缀更新旧行。

手动 pending 和 default 系统批次进入同一个调度器。运行中仍取出系统缓冲并排队；若读取 default 失败，保留路径与错误供重试。新增 pending 不改变运行批次分母。批次选择器只提供会话内结果，不称为历史记录；「再压一批」不影响排队的系统任务。

重试创建新 jobId / attempt，随 submit 原子入队，不能被同路径 pending 去重丢弃；旧结果保留来源关联，不自动循环重试。

### 9.4 文件信息与预览

`inspect_images(paths)` 逐项返回 canonicalPath、字节、魔数格式、可选 width / height 和错误；单项不可读不阻塞其它图片。用 core `sniff` 与 `/usr/bin/sips` 探测尺寸。

对比先调用 `image_source(path)` 逐文件授权，再由 WebView 解码真实原图 / 产物；适应窗口与原始尺寸只改变 CSS 显示比例，共用同一图源。解码失败才调用 `image_preview(path,0)` 生成无损原尺寸 PNG，不再生成 1600px 对比图。

`image_preview(path,maxEdge)` 仅支持 192（列表缩略图）、0（原尺寸显示副本），返回缓存绝对路径与 leaseId；生成与缓存命中均逐文件授权，支持隐藏目录。缩略图按视口懒加载，组件退出或图像失败时调用 `release_preview` 释放租约；对比退出释放副本引用。动图注明静态预览；无法显示时提供占位，不影响处理与定位。

副本只写入数据根 `cache/previews/`，键为 canonicalPath + mtime + size + maxEdge。使用 sips 参数数组、并发闸门（最多 2 项）和原子发布；维护锁协调跨进程生成与清理，文件共享锁保护使用中的预览。临时工作区统一 `cache/tmp/`，持独占租约，正常结束删除，异常退出由 OS 释放锁，遗留目录再由维护器回收。

缓存目标容量 256 MiB，闲置超过 24 小时过期；按较久未使用者优先回收。发布 / 释放 / 临时任务边界触发维护，App 启动及每 5 分钟补充扫描，设置可手动清理闲置项。活动文件和正在处理的工作区可暂时超出预算，释放后恢复回收；旧无租约目录仅过期后清理。只管理 cache 下 previews / tmp / clipboard，不跟随符号链接，不触碰原图、产物、配置和撤销记录。

### 9.5 输出路径与已知风险

内核现有输出命名与历史产物同名时可能替换已有产物。本卡不宣称有全新“永不覆盖结果”能力，也不扩大为目录级撤销或重压工具。

- GUI 默认保留原图、非空后缀；已有输入同名保护继续由 core 负责。
- 对重新添加已完成输入、失败重试可能已有产物的情况，操作前说明“同名处理结果可能被替换，原图保留”，用 AlertDialog 明确确认后执行；取消保留待处理项。
- 不同目录同名输入汇入统一输出目录时，开始前检查可确定的相同命名族（输入 stem、实际输出格式族（含 TIFF 自动转 JPEG、GIF 转 WebP）、渲染后缀）。冲突项留待处理并提示更换输出目录/后缀，不并发争写同一路径。含 `{size}` 也按相同 stem/后缀模板保守判冲突，不以未知体积假装可确定最终名。
- 这类预检只保护 GUI 当前批次；不把它当成 CLI/watch 跨进程锁。算法、跨进程落盘保证和 undo 清单并发属于后续核心工作。
