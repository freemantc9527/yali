goal: 实施用户确认的五项方案：紧凑底栏、两行图片行、同原图换方案重处理、256 MiB / 24h 缓存回收、真实文件对比。
status: 已实施，待人工验收（2026-11-19）

## 范围与约定

- 保持现有字体、配色与组件，底栏集中显示完成数和节省量，图片行按文件 / 结果 / 操作分组。
- 默认处理待处理图片；没有待处理项时，复用当前原图重新处理。每次执行使用独立 job/batch，主列表只显示同原图的最新任务；旧批次仍可查看，不把处理产物作为下一次输入。
- 常见格式直接读真实输入 / 产物；适应窗口和原始尺寸共用图源。无法解码时才生成原尺寸 PNG。
- 缓存目标容量 256 MiB、闲置 24h 过期；使用中的文件受跨进程锁保护，可暂时超出预算，释放后恢复回收。生成 / 释放 / 临时任务边界、启动及常驻每 5 分钟维护。临时工作区正常结束删除，异常遗留延迟回收。
- 设置显示缓存占用、容量与清理入口；仅管理应用 cache，不删除图片、配置或撤销记录。

## 原因与实现

- `App.start` 原先在无 pending 时清空列表并重新选图；现在用 `processingJobs / repeatJobs` 从原图建立新任务，确认后按当前参数执行。默认显示 `latestJobs`，单图移除同时移除旧 attempt，旧批次仍可单独查看。运行时底栏只统计活动 batch，避免旧结果混入新批进度。
- 底栏用两行文字呈现状态 / 节省量与保存说明；任务行以文件、结果、操作分组，次要动作归入更多菜单。复用现有组件与主题，不引入新样式系统。
- `displayImage` 直接解码真实文件，失败才取原尺寸 PNG；Viewer 缩放只改显示尺寸，不重新生成副本或重算 SSIM。列表继续懒加载 192px 缩略图。
- 新增 `yali_core::cache` 统一 previews / tmp / clipboard 的统计、容量与过期维护；维护锁协调发布和清理，预览共享锁 / 工作区独占锁保护活动文件，进程退出自动释放。扫描不跟随符号链接，容忍处理中间文件被移除；设置手动清理只清闲置项。TempDir 复用核心生命周期，GUI / CLI 使用同一规则。
