# T-024 · 图片预览修复与对比交互

goal: 恢复任务缩略图与适应窗口预览；明确原始尺寸，并支持尺寸变化后的合理对比。
manual-check: 待人工验收

## 根因与实现

- 缩略图和适应窗口都读取 `~/.yali/cache/previews/`。Unix 上 Tauri 的 `**` 默认不匹配隐藏目录；sips 成功生成的 PNG 被 asset protocol 拒绝，原始尺寸直接读取原图因此正常。
- `preview::generate` 对成功生成和缓存命中的预览逐文件 `allow_file`，不全局开放隐藏目录。回归使用真实 Tauri Scope、项目配置及含空格/方括号的隐藏缓存目录，覆盖 192 / 1600 / 0、全新 scope 的缓存命中和无关文件仍被拒绝。
- “100%”改为“原始尺寸”，方框图标替换放大镜；按实际像素显示，超出窗口可滚动。
- 同尺寸默认叠加；不同尺寸默认并排，各自在可用宽高内完整显示，标注两侧像素尺寸。可切换叠加并拖动分割线：适应窗口按画面对齐、保持比例；原始尺寸按各自实际像素居中。尺寸不同时明确 SSIM 不适用。
- 复用窗口测量与适配计算，图片不拉伸；分割线补充 slider 语义、值和 pointer capture 释放。加载失败显示明确状态。

## 验证（2026-11-19）

- 修复前：`rtk bypass cargo test -p yali-app preview::tests -- --nocapture` 真实复现 `asset protocol denied …/.yali [test]/cache/previews/….png`。
- 修复后：同一回归通过；`cargo test -p yali-app` 20 项通过。
- `pnpm --dir ui test` 65 项通过；`pnpm --dir ui build` 通过。
- `bash scripts/build.sh` 通过：真实前端、自包含 App、111 个 Mach-O 动态依赖和 ad-hoc 签名、10 类图片 / UTI 校验。
- 浏览器加载真实 canvas PNG 文件：2400×1600 原图、1200×800 缩小图、800×1600 竖图、同尺寸输出；缩略图加载成功。尺寸不同默认并排、同尺寸默认叠加，切换任务重置默认；原始尺寸保留 2400×1600 / 1200×800，适应窗口保持比例；分割线键盘 50→51 且 clip 同步。980×640、640×420 无页面横向溢出，最小窗口中横/竖图均受可用宽高约束。
- 最终原生 App 真实处理 JPEG 531019→49178 bytes。截图确认任务缩略图和适应窗口图片实际绘制；SSIM 0.9647。CoreGraphics 鼠标拖动分割线，AX 值 50→72；640×420 原生窗口中两张预览均为 351×235，分割线可达；切换原始尺寸后实际宽度恢复 1920px。
- 原生尺寸变化场景未完成：文件选择器的路径确认自动化未成功，已取消面板；不同尺寸布局已在浏览器实测，原生触控手感仍待用户亲验。浏览器和自动化均不标为人工验收。
