# ADR-007 · GitHub macOS 双架构发布

> 状态：接受，云端验证待完成 · 日期：2026-11-19 · 用户选择首批 Apple Silicon + Intel

## 背景

项目已有自包含 macOS App，分发约束沿用 [ADR-006](ADR-006-self-contained-app.md)。需要减少本机构建与手动收集产物，首批仅扩展到 macOS 两种架构。

## 决策

- 本地包仅自用和本地验证，不用于发布。Release 资产只接收本仓库本次 GitHub Actions 运行生成的两个架构产物，记录云端运行来源，不接受本地补传。
- GitHub Actions 分别在 `macos-15` 和 `macos-15-intel` 原生构建，固定 Rust、pnpm、Tauri CLI 版本；原生工具链与所有内嵌引擎架构必须一致。
- 复用 `scripts/build.sh` 及其依赖重定位、许可证收集和签名检查，随后运行隔离 smoke 与质量金样。官方 Tauri Action 的默认打包不能替代现有 finalize 流程，本轮不引入该 Action。
- 每架构输出保留 App 结构的 zip 与构建记录，汇总后生成 `SHA256SUMS`；最低系统从各自运行时清单提取，不承诺与本机包或另一架构一致。
- 手动运行仅构建；`v*` 标签触发时须与全部版本字段一致、指向 main 历史，两架构全部通过后创建 Release 草稿。公开发布由维护者核对验收与资产后执行。
- 构建任务只读，只有草稿任务使用自动提供的 `GITHUB_TOKEN` 写 Release；无自建 PAT、Apple 证书或额外第三方服务。
- Release 已存在时失败，不覆盖资产。上传失败可能留下部分草稿，须核对远端后处理，不盲目重试或删除。

## 取舍与边界

两个独立原生包比 universal 包更易核验；universal 需要主程序、CLI、所有引擎及动态库完整合并，不能只 lipo 主程序。自托管机器会增加维护成本，当前公开仓库先使用 GitHub 标准 runner。

Homebrew 安装来自运行时仓库，构建记录会保存实际依赖版本；固定 runner 与工具版本不等于二进制可逐位复现。依赖升级若触发质量或兼容失败，阻断发布，不自动修改基线或降低最低系统声明。

CI 自动通过只证明记录的自动路径；Finder 可见性、原生交互与 Gatekeeper 首次运行仍需人工验收。云端 runner、依赖可用性和 Intel 完整链路在首次工作流运行前均不能宣称已验证。

回退可用新提交停用工作流，不涉及用户数据或系统安装；已公开版本不覆盖，修复采用新版本。
